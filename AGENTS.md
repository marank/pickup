# Pickup — conventions for contributors and coding agents

Photo/video sharing without accounts. Django backend (`backend/`, API via Django REST framework), Vue 3 + TypeScript SPA (`frontend/`), one hardened Docker image. Read this before changing structure; `README.md` has setup and commands.

## Commands

VS Code tasks (`.vscode/tasks.json`) hold the everyday commands; the README lists the plain equivalents.
- `dev` task: Django :8000 + Vite :5173 → http://localhost:5173.
- `check` task runs everything CI runs. It must pass before a commit is pushed. If you change a check, change it in both `tasks.json` and `.gitea/workflows/build.yaml`.
- `api: types` after any API change (schema → `frontend/openapi.json` → `frontend/src/api/schema.d.ts`); commit both files. CI fails if either is stale.
- `django: makemigrations` after model changes; commit the migrations.
- Frontend package manager is **pnpm** only. Backend dependencies via `uv add` / `uv add --dev`.
- `uv tool run pre-commit install` once per clone (ruff, prettier, oxlint on commit).

## Domain rules (access control)

Members have no accounts. Keep these properties; tests in `apps/pickups/tests/` cover them.
- A member's personal link carries `Member.access_key`; `POST /api/pickups/{id}/session/` trades it for a Django session (`services/members.py`). The link's page (`MemberLinkView`) first shows whose link it is (`POST .../session/preview/`, no login) and only logs in when the button is pressed. Member ids are never credentials and never appear in API responses or URLs. `access_key` is returned only to that member (when creating or joining, and from `GET .../session/link/` while signed in), in the email, and to the creator one member at a time (`GET .../members/{id}/link/`, for a lost link; never in the member list).
- The pickup id is the share link, so `Pickup` keeps a random UUIDv4 (not the time-ordered UUIDv7 of `UUIDModel`).
- Every unsafe request is CSRF-checked, also for anonymous members (`apps.core.api.authentication.CsrfSessionAuthentication`).
- A pickup may have a password (`Pickup.password`, a `make_password` hash; `set_pickup_password`). Without a login, the browser then gets nothing but `password_required` (no title, no contents, also not with `visibility == "link"`); joining and logging in with a personal link take the password in the same request (`check_pickup_password`, the join view checks it before anything else). Setting or changing it raises `Pickup.access_version`; logins store the version (`login_member`) and older ones no longer count (`get_member_from_request`), except the creator's who set it.
- Who may do what lives in `services/access.py`; use it instead of ad-hoc checks. Seeing a pickup's folders, media and files needs `can_view` (a member, or `visibility == "link"`; with `visibility == "creator"` — closed — only the creator); outsiders get only its title and how to join (counts are 0). Changes to a folder need `can_edit` (owner, and the pickup not closed for them), never `member.owns()` alone. Joining follows `Pickup.join_policy` (`open` | `invite` | `closed`, `services/members.py`); a new participant must pick a name nobody in the pickup has (case-insensitive), so nobody can pose as someone else. Members change their own name and their top-level folder's name with `PATCH .../session/` (`update_member`): same uniqueness rules, and their folders' `user_name` follows. The creator may delete any subfolder or file (moderation), remove members (with their folder) and delete the whole pickup (`delete_pickup`: files on disk after commit, chunk directories, rows), never a top-level folder through the folder API. A creator who gives a name when creating gets a folder with that name.
- Viewsets expose only the actions the SPA uses; changes to a folder or its media require `member.owns(folder)`, which checks the folder's top-level folder (`Folder.root`), so subfolders belong to the member who owns the top-level folder.
- Folders nest: `Folder.parent` is the containing folder, `Folder.root` the member's top-level folder (both empty for top-level folders). A member's top-level folder can be renamed but not deleted. Names are unique per parent (case-insensitive) and may not contain `/` (the address bar's separator). Subfolder logic lives in `services/folders.py`.
- Email addresses (`services/identity.py`): always store `Member.email_hash` (HMAC with `EMAIL_HASH_KEY`, which must never change); the plain `Member.email` only while the pickup's `email_privacy` is off. Mails go out at the moment an address is entered (`services/mail.py`; built in the request, sent by a small thread pool after the transaction commits, `MAIL_IN_BACKGROUND` is off in tests; sender "<name> via Pickup", reply-to only with a plain address; plain text plus HTML with the logo embedded, never loaded from the server), so nothing needs the plain address later. A member who already has an address and enters a different one (`set_email`) only gets a confirmation link at the new address; it carries the address signed (`django.core.signing`, 24 h) after the `#`, so it never reaches server logs, and nothing is stored until `confirm_email`. Endpoints that send mail must not reveal whether an address is known (`link-request` and the start page's `POST /api/pickups/lookup/` — all live pickups of an address with its personal links, found by the hash — always answer 202), respect `Member.link_sent_at` (cooldown) and stay in nginx's `mail` rate limit.
- Creating pickups follows `PICKUP_CREATION` (`everyone` | `code` | `none`, `services/creation.py`). With `code`, nothing is remembered: the SPA checks a code (`POST /api/pickups/creation/`) before showing `/create`, keeps it only in memory and sends it with the new pickup, where `create` checks it again (constant-time against `PICKUP_CREATION_CODES`). Both are in nginx's `mail` rate limit.
- Expired pickups (`expires_at` passed) count as gone: query pickups through `models.live()` (also across relations, `live("folder__pickup__")`), never `is_active=True` alone. The supervisord program `expiry` runs `delete_expired_pickups` hourly.
- ZIP downloads (`services/archive.py`) are streamed with stdlib `zipfile` into a write-only sink — no temp files, stored not deflated. Archive paths go through `safe_name()`.
- Files are never served publicly: the API returns `/api/files/{id}/`, which checks `can_view` and then hands the file to nginx via `X-Accel-Redirect` (`MEDIA_ACCEL_REDIRECT`; natively Django streams it). Don't add a public `/media/` location.
- Storage limits live in `services/storage.py`: every upload path calls `check_room()` (direct upload, upload-session start, finalize); pending upload sessions count with their full size. Defaults from `PICKUP_STORAGE_LIMIT` / `MEMBER_STORAGE_LIMIT`, per-pickup overrides in `Pickup.storage_limit` / `member_storage_limit` (null: default, 0: unlimited), set with `manage.py storage_limits`.
- Uploads: images and videos only, no SVG; stored under random names below `DATA_DIR`. Files above 20 MB go through the chunked upload API (5 MB chunks), because nginx limits request bodies to 25 MB.
- Previews: every upload path calls `create_thumbnail()` (`services/thumbnails.py`): a JPEG of at most 640 px, upright, stored in `Media.thumbnail` and served like the file at `/api/files/{id}/thumbnail/`; tiles load it instead of the file. Images go through Pillow; videos give a still from ffmpeg (run as a subprocess with a timeout and `-format_whitelist`, so playlists can't make it read other files). The image builds its own small LGPL ffmpeg from Debian's source in the `ffmpeg` stage of the `Dockerfile` (Debian's package would add ~440 MB); a new container or codec for uploads must be enabled there and in `VIDEO_FORMATS`. Trivy doesn't see that binary, so it gets Debian's fixes only when the image is rebuilt. CI tests with Debian's full ffmpeg package. Failing files keep none (the tile falls back to the file); the supervisord program `thumbnails` runs `create_thumbnails` once per start for files still without one; on SIGTERM it finishes the current file and exits, so the container stops normally (there is no job queue, keep it that way unless more background work comes up). A preview is stored only if the row has none yet, so an upload and the backfill never both keep one. Deleting media goes through `Media.delete_files()` so the preview goes too. Never let the browser make previews.

## Backend rules

- Apps live in `backend/apps/<name>/` (`name = "apps.<name>"`, `label = "<name>"`), registered in `INSTALLED_APPS`. Domain app: `apps/pickups`.
- **No monolithic modules.** `models/`, `admin/`, `api/`, `serializers/`, `services/`, `tests/` are packages with one file per model/resource; `__init__.py` re-exports explicitly. Relations use string references (`"pickups.Folder"`).
- **Every model inherits `apps.core.models.UUIDModel` or `TimeStampedModel`** (UUID primary key). `manage.py check` fails (`core.E001`) otherwise. Order queries explicitly.
- Business logic goes in `services/`, not in API views or models' `save()`.
- API: under `/api/`, paths end in `/` (DRF router default; keep it consistent), session auth + CSRF, UUIDs in paths. `/api/health` stays unauthenticated and exactly at that path. Annotate views with `extend_schema` so the OpenAPI schema stays warning-free (CI runs `spectacular --fail-on-warn`).
- Configuration only via environment variables read through `config/env.py`; every new variable gets a commented entry in `.env.example`.
- mypy runs in strict mode; type all new code. Coverage must stay ≥ 90 %.
- No GPL/AGPL/SSPL dependencies (CI license check).

## Frontend rules

- Feature folders: `src/features/<feature>/{components,composables,views}` (`home`, `pickups`, `explorer`), routes in `src/router/routes/<feature>.ts`.
- The pickup page is a file explorer (`features/explorer`). `provideExplorer()` in `ExplorerView` creates one shared state (tree, current folder, items, selection, view preferences, uploads, dialogs); components read it with `useExplorer()` instead of passing props down. Pure logic lives in `explorer/lib` (`tree.ts`, `items.ts`, `actions.ts`) and is unit-tested; item actions are defined once in `lib/actions.ts` for the context menu and the "⋮" menu.
- The creator's pages (`/pickup/{id}/settings`, `/people`) are explorer "pages": linked at the bottom of the folder tree, shown in the content pane (`PagePane`) with their own address-bar segment. Prefer such pages over modal dialogs for anything bigger than a short form.
- Interaction rules: mouse click selects (Ctrl/Shift for more), double-click opens, dragging on empty space draws a selection rectangle (`useMarquee`); touch tap opens (decided by the `pointerdown` before the click: WebKit's click has no `pointerType`). The media viewer takes touch itself (`useViewerGestures`, geometry in `lib/gestures.ts`): the pictures follow a sideways swipe, swipe down closes, pinch and double-tap zoom, a zoomed picture pans, a tap hides the bars. Keyboard: Enter, F2, Delete, Backspace, Ctrl+A, Escape, Ctrl+L. Everything must stay usable on a 375 px wide screen. Below 640 px (`usePhone`) the explorer has its own layout: the title in the header (`PickupBar` teleports to `#header-pickup`), `MobileToolbar` instead of `NavBar`/`CommandBar` (new commands go into its menu too), `UploadFab`, no status bar.
- Logo: defined once in `src/lib/brand.ts`. The mark is an outlined picture tile with a tilted tomato tile lifting off it (`PickupMark.vue`, also the pickup's icon in the tree and address bar). The wordmark is “pickup” in Bricolage Grotesque 800, optical size 96, tracking −0.035em, stored as outlines; the i's dot is the tomato tile. Frame and letters take the text colour, the tile is always tomato. Use `PickupLogo.vue` / `PickupMark.vue`, never re-draw it or set the word in the font. Derived files: `public/favicon.svg`, `favicon.ico`, `apple-touch-icon.png` (ink badge) and the mail logo `backend/apps/pickups/assets/mail-logo.png`; regenerate them when the shapes change. Other proposals live in `design/logo/`.
- Design tokens are CSS variables in `src/assets/main.css` (paper, ink, tomato, butter, sage, owner colours); use the Tailwind names (`bg-pane`, `bg-selection`, `text-tomato`, …) instead of raw colours. The colour scheme (system/light/dark) is a stored setting in `lib/theme.ts`, offered in the header's account menu.
- Server state via TanStack Query composables around the typed `api` client (`src/api/client.ts`); wrap calls in `unwrap()` so errors become `ApiError`. Query keys of a pickup start with `['pickup', id]` (`features/pickups/queryKeys.ts`); invalidate that prefix after changes. There is no Pinia: the app has no client-only state. Add it only if that changes.
- Files go as multipart via `formBody()`; uploads run through `useUploadQueue`.
- UI components from shadcn-vue (`pnpm dlx shadcn-vue@latest add <component>`) in `src/components/ui/` — vendored, edit freely. The CLI is not a dependency; `src/assets/shadcn.css` holds the CSS it would import. `add` re-inserts a Google Fonts `@import` into `main.css`; remove it (a test fails otherwise).
- Tailwind for styling. No inline `<script>`, no remote scripts, fonts or styles: the CSP only allows our own origin (fonts are self-hosted via `@fontsource-variable`).
- Tests: Vitest + @vue/test-utils; `src/test/fakeApi.ts` replaces `fetch` with a route table. Coverage ≥ 90 % over `src/` (without `components/ui`).
- Never edit `src/api/schema.d.ts` by hand.

## Docker / runtime

- The app container runs read-only, without capabilities, as an unprivileged user. Only `/data` (`DATA_DIR`, uploads) and `/tmp` are writable — new features must write there, not loosen the hardening.
- supervisord runs gunicorn, nginx and the hourly `expiry` cleanup; nginx serves the SPA, delivers uploaded files from the internal `/protected-media/` location after Django's check, and proxies `/api` and `/admin`.
- `/admin` is closed in Docker unless `ADMIN_ENABLED=true`.
- Backups (`docker/backup.sh`): nightly database dump plus hard-linked media snapshot. Anything new under `/data` that must survive belongs in that script too.
